# AGENTS.md — qcore

Rust workspace (edition 2021, pinned toolchain `1.97.1` via `rust-toolchain.toml`). Multi-protocol VPN tunnel core: engine + plugin transports + CLI + C/JNI FFI.

## Commands (use these exact forms)

- Local gate (fast CI subset): `cargo xtask ci` — runs `fmt --check` → `clippy --workspace --all-targets --all-features -- -D warnings` → `nextest --workspace --all-features --exclude tests-conformance` → `nextest -p tests-conformance` → `deny-sync` → `notices --check` → `abi-diff` → `smoke --target native`.
- Full CI gate (`.github/workflows/ci.yml`) adds: `cargo deny --config denylist.toml check`, semver-checks (git-baseline), gitleaks + trufflehog secret scans.
- `cargo xtask` alias comes from `.cargo/config.toml`. Subcommands: `build|smoke|package|release|abi-diff|deny-sync|notices|ci`.
- Test runner is **nextest**, not `cargo test`. Single area: `cargo nextest run -p qcore-core --lib chain::` (also `config::`, `session::`, `scan::`, `identity::`, `diag::`). Conformance is a separate line: `cargo nextest run -p tests-conformance`; chains (`-p tests-chains`) rides the workspace run.
- Always pass `--workspace` for clippy/nextest: `default-members` is only `qcore/cli/ffi`, so without it the `qcore-core`/transports/examples/xtask suites silently never run.

## Architecture (non-obvious)

- Facade: embedders depend on `crates/qcore` only (pure re-exports); never import `qcore-core` or a transport crate directly. Engine surface is `qcore_core::api::Engine`.
- Plugin boundary (`crates/qcore-transport-api`): three traits (`HopFactory` / `RunningHop` / `Dialer`) + static `TransportDescriptor`. Engine reads the `inventory`-built `TransportRegistry` (`crates/qcore-core/src/registry.rs`) and **never matches on a transport kind**. Adding a transport = 7 edit points — see docs/transport-authoring.md.
- Binaries/tests must call `qcore_transports::linked_kinds()` once at startup, or static-archive GC drops `register_plugin!` submissions and the registry is empty.
- Features: `qcore-transports` default = `wireguard,masque,relay,psiphon,mock`; `tor` is opt-in. FFI links `tor` too.
- `profiles/` is data, not code: `scan.toml` (`turbo|balanced|stealth`), `obfuscation.toml`, `compositions.toml` (presets `gool` = 2× `wireguard peer=warp`, `mim` = 2× `masque alpn=h3`, `tor-warp`). Chain depth default 3, hard limit 5 (`--max-depth 1..=5`).
- `crates/qcore-core/src/`: `api/` (Engine) · `chain/` (grammar/preset/validate; single `allowed_fields()` table) · `config/` · `session/` (lifecycle, watchdog: Failed→Degraded→rebuild×3→Failed; keepalive default 25s, `--keepalive off`, tunnel DNS resolver for SOCKS5 domain targets, control channel, proxy) · `scan/` · `identity/` · `diag/` (redaction).

## Gotchas / contracts

- CLI (`crates/qcore-cli`): stdout = results (with `--json`, exactly one JSON doc), stderr = diagnostics as `qcore: <msg> (exit N)`. Exit codes: 0 ok · 1 session dead (status verdict, not an `EXIT_*` constant) · 2 invalid chain · 3 hop failure · 4 scan empty · 5 import rejected · 6 usage · 10 no session · 12 unverifiable — source of truth: `contracts/cli.md` §2. `preflight` opens zero sockets; `ls --json` is rejected (exit 6); empty `scan` is exit 4 — with `--json`/`--output json` the `{"candidates":[]}` doc goes to stdout, table mode prints nothing on stdout and the diagnostic on stderr.
- FFI (`crates/qcore-ffi/qcore.h`): generated by cbindgen — never hand-edit. `abi-version.txt` must mirror `ABI_VERSION` in `qcore-core/src/api/version.rs` (build.rs enforces). `cargo xtask abi-diff` checks header↔source symbols both directions + empty committed `qcore.h` diff (fails closed without git; `--allow-diff` only during a versioned ABI bump).
- Secrets: typed wrappers, `Debug` prints exactly `<redacted>`; mask via `masked_value` / `masked_failure_line`; conflicting license inputs exit 6, `--license-file` is the recommended form (`--license-key` is argv-visible and warns). Gitleaks + trufflehog `--only-verified` block the gate.
- Supply chain: `cargo deny --config denylist.toml check` + `cargo xtask deny-sync` (proves every `skip` entry still matches a duplicate and every duplicate has a skip). `denylist.toml` `skip` pins older duplicate majors (mostly `arti-client 0.46` subtree) — any *new* duplicate fails.
- Transport impl rules: timeout on every dial/handshake/readiness path; `tokio::Mutex` may be held across await, `std` locks never on async paths; `HopFactory::build` must be cancellation-safe (engine races it with `timeout`; partial sockets/sidecars owned by the future, released on drop); parse boundary into typed configs, fail closed naming the field; bare `unwrap()` → `expect(reason)`; bind via `unspecified_bind(dst)`, never parse `"0.0.0.0:0"` literals. New `HopFactory` trait methods get defaults, never breaking.
- Per-area conventions + fastest verify commands: `docs/rust-practices.md` (constitution wins on conflict).

## Release (do not improvise)

- `xtask/src/targets.toml` is the 9-target contract (Windows MSVC native; Linux via cross-rs; Android via cargo-ndk; musl: future — no musl triple in targets.toml yet, the cargo-zigbuild backend exists for it in xtask/src/build.rs). Removing/demoting a target needs a constitution amendment.
- `release.yml` runs all 9 contract targets on a tag push or a `workflow_dispatch` dry run: Windows native MSVC, linux-gnu via cross-rs 0.2.5, android via cargo-ndk 3.2.0 + NDK r27. Each leg runs `cargo xtask build|smoke|package --target <triple>` and uploads only its own archive; `finalize` signs the merged set, and `publish` is skipped unless `github.ref` is a tag. Coverage is parsed from that file at compile time and diffed both ways against `targets.toml`, so editing one side alone fails closed.
- **Do not tag `v*`** until one green `workflow_dispatch` run of `release.yml` shows all nine legs building, smoking and packaging (it publishes nothing). `cargo xtask release` fails closed when `release.yml` and `targets.toml` disagree; `--allow-partial-matrix` only acknowledges a deliberately partial matrix.
- Disk: CI wipes `target/` + registry cache before semver baseline builds (~14 GB runner limit) and prunes `target/semver-checks` after; replicate if adding heavy jobs.

## CI/CD process (2026-11 normalization)

- Branch model: `main` is the only long-lived branch (`dev` and `master` are retired); PRs target `main`. Renaming or reshaping a CI job means updating branch protection's required checks in the same change.
- Required checks on `main`: `supply`, `clippy`, `test`, `conformance (1/2)`, `conformance (2/2)`, `semver`, `gate-windows`, `go-consumer` — 1:1 with jobs in `.github/workflows/ci.yml`, so a rename must be paired with a GitHub settings change.
- Merge queue is configured in the GitHub UI (Settings → Branches → protection rule for `main` → Require merge queue; merge commit, build concurrency 3, timeout 90 min, min/max 1/1). The REST ruleset API rejects the `merge_queue` rule on this account — do not try to script it. `ci.yml` already listens on `merge_group`.
- Release gate: `publish` is gated by the `release` environment (required reviewer), and a `v*` tag ruleset blocks updates/deletions. Never tag until one green `workflow_dispatch` run of `release.yml` shows all nine targets building, smoking and packaging. These settings live in GitHub, not the repo.
- Tool pins are load-bearing: `nextest-version = "0.9.150"` in `.config/nextest.toml` fails closed below that version, so every workflow installing nextest must use >= 0.9.150 (currently 0.9.152); cargo-deny 0.22.0 and cargo-semver-checks 0.51.0 must match across `ci.yml` and `release.yml`. All `uses:` are SHA-pinned with trailing `# vX.Y.Z` comments so Dependabot can still update them — keep the comments.
- Cache: Linux CI jobs share `shared-key: v3-linux-ci`, and only `main` saves (`save-if: refs/heads/main`). Bump the key if a restored tree ever poisons a build (the old `v2-pruned` SIGBUS incident). Each release matrix leg has its own `release-<triple>` key.
- Signing: cosign v3 requires `--bundle SHA256SUMS.sigstore.json`; do not reintroduce `--output-signature`. `actions/attest@v4` adds GitHub-native SLSA provenance; `id-token: write` and `attestations: write` live only in the finalize job.
- Runners: linux/android legs use `ubuntu-24.04` with the image's NDK pinned via `ANDROID_NDK_HOME` (no sdkmanager install); Windows legs stay `windows-2022` / `windows-11-arm`. `xtask/src/targets.toml`'s `runner` field must match `release.yml`'s matrix rows — xtask parses both at compile time and fails closed on drift.
- Local gates: `cargo xtask ci` (fmt, clippy, nextest, conformance, deny-sync, notices, abi-diff, smoke) plus `cargo deny --config denylist.toml check`. The local `abi-diff` semver fallback fails on Windows/boringtun and is non-blocking by design; CI uses the pinned git baseline instead.
- Scanner downloads: gitleaks and trufflehog tarballs must be checksum-verified against their same-release `*_checksums.txt` before install, in both the CI supply and release gates; keep findings redacted.
- Dependabot: minor/patch updates are grouped per ecosystem with a 3-day cooldown (security updates exempt). SHA-pinned actions need their version comments to stay updatable.
